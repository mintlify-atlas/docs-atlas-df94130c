`/make-resume` is the core generation skill of Claude Resume Kit. It reads a job description, runs live web research on the target company, builds a bullet selection plan you review and approve, then generates character-precise LaTeX output section by section — running char count, page fill, and compile gates before handing control back to you.

## Command Syntax

The simplest invocation passes just a JD file path:

```bash
/make-resume JDs/target_job.txt
```

Add a focus directive after the path to influence bullet selection and reframing:

```bash
/make-resume JDs/target_job.txt Focus: emphasize ML pipeline work
```

Enable Quick Mode to skip the two confirmation stops and auto-select bullets from the Priority Matrix:

```bash
/make-resume Quick: JDs/target_job.txt
```

<Note>
Quick Mode selects all HIGH priority achievements from the bundle's Priority Matrix as 2L bullets, fills the remaining budget with MEDIUM priority bullets in matrix order, and defaults to a 2-page resume unless the JD clearly calls for a CV. Budget Gate and end-of-resume STOP are still enforced.
</Note>

## The Three Phases

`/make-resume` runs three sequential phases, each ending with a mandatory stop before proceeding.

<Steps>
  <Step title="Phase 0: Research & Session Setup">
    The skill reads your JD, `resume_builder/reference/resume_reference.md`, and `config.md` to identify the correct role-type bundle. It then runs **2–3 mandatory web searches** on the company:

    1. `[Company] research & development [key JD domain]` — products and recent projects
    2. `[Company] [specific technology from JD]` — concrete hooks for the cover letter
    3. `[Company] careers [role type] culture` or recent news — hiring context

    From this, it produces five structured artifacts and writes them into a new session file at `output/<FolderName>/session_<name>.md`:

    | Artifact | Contents |
    |----------|----------|
    | **JD Analysis** | Requirements table (Direct / Bridge / Gap), ATS keywords by category |
    | **Company Context** | Mission, role purpose, culture signals, "why them" angle |
    | **Framing Strategy** | Lead narrative, reframing map, emphasize/downplay directives |
    | **Critique Context** | Reviewer persona, competitive landscape, domain vocabulary |
    | **Cover Letter Plan** | Institution type, paragraph structure, hooks, jargon level |

    The session file is verified for completeness — all 8 required sections must be non-empty before the stop.

    **MANDATORY STOP:** Confirms role type + bundle, format (resume vs CV), and framing strategy. You must respond explicitly before Phase 1 begins.
  </Step>

  <Step title="Phase 1: Plan Bullets">
    The skill reads your bundle's Priority Matrix, all experience files in `resume_builder/experience/`, the achievement reframing guide, skills taxonomy, and pub metadata. It then presents one selection table per position:

    ```
    [Position Name] (Budget: N-M bullets, ~X-Y rendered lines)

    |   | ID   | Achievement                   | Variant | Lines | JD Match |
    |---|------|-------------------------------|---------|-------|----------|
    | * | P1-1 | Enzyme Stability Screening    | 2L      | 2     | Direct   |
    | * | P1-5 | Transfer Learning Framework   | 2L      | 2     | Direct   |
    | o | P1-3 | Automated Screening Pipeline  | 2L      | 2     | Bridge   |
    | x | P1-7 | Mentorship Program            | --      | --    | Weak     |
    ```

    **Legend:** `*` = recommended | `o` = available | `x` = not recommended

    After all positions, the plan shows: total bullets vs budget, remaining slots, provenance-forced exclusions, and how your focus directive changed defaults. For CVs, it confirms the first bullet of the first experience is a 2L (page 1 rule).

    **MANDATORY STOP:** You confirm or modify the selection. The session file is updated with the confirmed plan before Phase 2 begins.
  </Step>

  <Step title="Phase 2: Generate">
    **Budget Gate** runs first: total bullets and rendered lines are checked against the Quick Budget Card from `resume_reference.md`. Generation does not begin on a FAIL.

    The skill generates section by section — Summary, Technical Skills, then each position's bullets — running `char_count.py` after every position:

    ```bash
    python3 resume_builder/helpers/char_count.py -f [resume|cv] output/<FolderName>/[file].tex
    ```

    The final document is saved to `output/<FolderName>/e2e_<name>_resume.tex` (or `_cv.tex`). After all sections, the Post-Generation Verification checklist from `resume_reference.md` is run in full before presenting results.

    **MANDATORY STOP:** Presents compilation summary (pages, char count results, any violations fixed). You confirm before receiving the `/make-cl` command.
  </Step>
</Steps>

## Quality Gates

Three gates enforce document correctness at generation time. Any failure is fixed before the skill moves on.

<CardGroup cols={3}>
  <Card title="CHAR COUNT GATE" icon="ruler">
    No OVER violations. Last line of every 2L bullet must be ≥ 70% full (orphan rule). Run after each position.
  </Card>
  <Card title="PAGE FILL GATE" icon="file">
    Resume: ≤ 3 lines white space on last page. CV: rendered line target from `resume_reference.md`. Run after all experience.
  </Card>
  <Card title="COMPILE GATE" icon="check">
    Clean `pdflatex` compile. Page count matches `config.md` Document Preferences. PDF is visually inspected for orphans and header wrapping.
  </Card>
</CardGroup>

## Focus Directives

Append directives after the JD path to override default Priority Matrix behavior. Multiple directives can be combined.

| Directive | Effect |
|-----------|--------|
| `Emphasize X` | Prioritize X-related achievements across all positions |
| `Downplay Y` | Reduce or omit Y-related bullets |
| `Include Z` | Force-include achievement Z regardless of matrix rank |
| `Lead with A` | Make A the first bullet in its position |
| `Make B a 2L` | Override default variant for bullet B |

```bash
/make-resume JDs/acme_ml_eng.txt Focus: emphasize ML pipeline work, downplay mentorship
```

## Session File & Recovery

Every JD gets a persistent session file at `output/<FolderName>/session_<name>.md`. If a session is interrupted, `/make-resume` reads the status field and resumes from the correct point:

| Status Found | Action |
|-------------|--------|
| Phase 0: DONE, Phase 1: PENDING | Resume at Phase 1 |
| Phase 1: DONE | Resume at Budget Gate |
| Phase 2: IN_PROGRESS | Read existing `.tex`, resume from checkpoint |
| Phase 2: DONE | "Resume already done. Run `/make-cl` next." |

<Warning>
All bullet content is sourced exclusively from `resume_builder/experience/` files. The skill will never fabricate achievements. The priority hierarchy is always **Accuracy › Relevance › Impact › ATS › Brevity**.
</Warning>

<Note>
After `/make-resume` completes, run `/clear` before starting `/make-cl`. A fresh context window produces better cover letters — the three-session workflow is intentional.
</Note>
