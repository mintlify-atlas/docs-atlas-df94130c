`config.md` is the single configuration file every skill reads at startup. It contains your personal information, document preferences, provenance tracking, and role-type definitions. Edit it before your first application — the skills will not produce correct output without your real details in place.

<Warning>
The email address in **Personal Info** is embedded in every generated output file — resume, CV, and cover letter. Set it correctly before your first generation. Changing it later requires regenerating all previously produced documents.
</Warning>

## Personal Info

Your contact details appear verbatim in every generated `.tex` file. All fields are written into the header block of the LaTeX templates.

| Field | Description | Example |
|-------|-------------|---------|
| `Name` | Full name, rendered in the document header | `Jordan Chen` |
| `Degree suffix` | Appended after your name in the header | `Ph.D.` |
| `Email` | Used in all outputs; must match Personal Info exactly | `jordan.chen@email.com` |
| `Phone` | Full number with country code | `+1 5551234567` |
| `Location` | City, State ZIP — appears in header | `Richland, WA 99354` |
| `LinkedIn` | Profile URL, or leave blank | `linkedin.com/in/jordanchen` |
| `Google Scholar` | Profile URL for the Scholar icon link | `scholar.google.com/citations?user=...` |
| `ORCID` | ORCID profile URL | `orcid.org/0000-0002-XXXX-XXXX` |
| `Website` | Personal or lab website, or leave blank | _(blank)_ |

If you do not have a Google Scholar or ORCID, leave those fields blank and remove the corresponding icon lines from the `.tex` templates.

## Document Preferences

These settings control page counts, bullet line variants, and the technical skills section layout. All generation skills read these values before producing any output.

| Setting | Default | Description |
|---------|---------|-------------|
| `Resume pages` | `2` | Page count for resume documents |
| `CV pages` | `5` | Page count for CV documents |
| `Resume bullet variant` | `2L` | All variable resume bullets are 2-line |
| `CV bullet variant` | `2L/3L mix` | Mix of 2-line and 3-line bullets in CV |
| `Skills config (resume)` | `4-3-2-2-2` | Skills section layout: 5 groups of 4, 3, 2, 2, 2 lines = 13 total lines |
| `Skills config (CV)` | `4-4-3-3-3` | Skills section layout: 5 groups of 4, 4, 3, 3, 3 lines = 17 total lines |
| `Immigration line` | `Yes` | Adds "Authorized to work in the United States" as a fixed line |

### Skills Config Format

The skills config string `4-3-2-2-2` defines the technical skills section as five groups, with 4, 3, 2, 2, and 2 lines per group respectively, totaling **13 lines**. Each dash-separated number is one group header row. For CV, `4-4-3-3-3` produces **17 lines** across 5 groups.

Changing the skills config alters the variable bullet budget. Adding one skills line (e.g., switching from `4-3-2-2-2` to `4-4-2-2-2`) removes one available variable bullet from the experience section. Adjust the experience bullet count accordingly.

## Provenance Flags

The Provenance Flags table is the core of the anti-fabrication system. Skills check this table before every output and will never claim unpublished work is published, claim internal tools are peer-reviewed, or use full-ownership verbs for shared work.

| Column | Description |
|--------|-------------|
| `Item` | The paper, tool, or result being tracked |
| `Status` | Publication state — see status types below |
| `Correct Framing` | Exact phrase template the skills must use in output |

### Status Types

| Status | Meaning | Required Framing |
|--------|---------|-----------------|
| `published` | Appeared in a peer-reviewed venue | Can say "published in [Journal]" |
| `under review` | Submitted and currently under review | "under review at [Journal]" — never "published" |
| `preprint` | Posted as preprint, not yet submitted | "preprint" — never "published" or "under review" |
| `draft` | Exists in manuscript form, not yet submitted | Omit publication claims entirely |
| `internal` | Unpublished tool or dataset, internal use only | "infrastructure I developed" — never imply peer-reviewed |

Every paper and tool that appears in your knowledge base should have a row in this table. Add rows as you extract new papers. Delete the placeholder examples before your first generation.

## KB Corrections Log

The KB Corrections Log records verified factual errors to ensure they are never re-introduced. Skills read this table before generation and cross-check all numerical claims and attribution against it.

| Column | Description |
|--------|-------------|
| `Correction` | Short label for the error category |
| `Details` | The exact correct fact and the incorrect version to reject |

Common entries include: corrected Spearman/R² values, correct author attribution for co-developed tools, accurate metric units, and corrected paper titles.

## Role Types

Each row in the Role Types table defines one target audience. The `/setup-build-kb` skill creates one bundle file per role type during knowledge base setup. The `/make-resume` skill uses this table to select the right bundle for each JD.

| Column | Description |
|--------|-------------|
| `Role Name` | Short label used in the Decision Tree and bundle filename |
| `Target Employers` | The employer category this role type covers |
| `Tier` | Evidence strength relative to your background — see tier guide below |
| `Bundle File` | Filename of the bundle in `resume_builder/bundles/` |

### Tier Guide

| Tier | Meaning |
|------|---------|
| **Tier 1** | Strongest evidence — your work directly matches what these employers want |
| **Tier 2** | Strong with targeted emphasis — your background is relevant but needs framing |
| **Tier 3** | Viable with careful framing — real gaps exist; use bridge mappings |

---

## Role-Type Decision Tree

The Decision Tree maps JD keywords to role types. The `/make-resume` skill reads this table during Phase 0 to determine which bundle to use and whether to generate a hybrid resume.

| Column | Description |
|--------|-------------|
| `If JD mentions...` | Keywords or phrases from the job description |
| `Primary profile` | The role type to use as the primary bundle |
| `Secondary (hybrid)` | A second role type to blend in for hybrid JDs, or `--` |

When a JD mentions keywords from two rows, the skill uses the Primary role type's Priority Matrix for achievement ranking and the Secondary role type's Reframing Map for 1–2 bridging bullets.

## FIXED Sections

FIXED sections are template blocks that are copied verbatim into every generated document, never modified during generation. List them here so every skill knows not to touch them.

Default FIXED sections:
- Education
- Publications (CV)
- Honors & Awards
- Header block (name, contact, links)

Add any additional sections you want protected — for example, an undergraduate research block with fixed bullets, or a computing resources section on a CV.

## Output Rules

These rules define the package format and output constraints applied to all generated documents.

| Rule | Default | Description |
|------|---------|-------------|
| `Email in all outputs` | _(same as Personal Info)_ | Skills verify this matches Personal Info before output |
| `Resume package` | `2 pages + 1-page cover letter` | Full submission = 3 pages |
| `CV package` | `5 pages + 1–2 page cover letter` | Full submission = 6–7 pages |
| `Output .tex files ONLY` | Always | Claude generates `.tex`; you compile locally with `pdflatex` |
