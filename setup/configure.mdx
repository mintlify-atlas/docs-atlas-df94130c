`config.md` at the repo root is the single file every skill reads. Fill it out once before your first real application — your name, contact details, provenance flags for each paper, and the role types you're targeting all live here. Nothing about your identity, accuracy constraints, or output preferences is hard-coded anywhere else; it's all in this one file.

## File structure

The config is divided into eight sections. The table below maps every field to what it controls and where it appears in generated output.

### Personal Info

These fields populate your header block in every `.tex` file Claude generates.

| Field | Required | Notes |
|---|---|---|
| `Name` | Yes | Full name as it appears on your CV |
| `Degree suffix` | Optional | e.g., `Ph.D.`, `M.S.` — appended after name in header |
| `Email` | Yes | Used in ALL output files — double-check before first generation |
| `Phone` | Optional | Include country code (e.g., `+1 5551234567`) |
| `Location` | Optional | City, State ZIP |
| `LinkedIn` | Optional | Full URL or leave blank |
| `Google Scholar` | Optional | Full URL or leave blank — remove from template if unused |
| `ORCID` | Optional | Full URL or leave blank — remove from template if unused |
| `Website` | Optional | Personal site or lab page |

<Warning>
The email in `config.md` is read directly into every generated `.tex` file, including the cover letter. Double-check it before your first generation — a wrong email in the header is an embarrassing mistake that LaTeX won't catch.
</Warning>

### Document Preferences

Controls page counts, bullet line variants, and skills section layout.

| Field | Default | Notes |
|---|---|---|
| `Resume pages` | `2` | Target page count for `/make-resume` |
| `CV pages` | `5` | Target page count for `/make-resume` when document type is CV |
| `Resume bullet variant` | `2L` | All variable bullets are 2-line (~189–205 rendered characters) |
| `CV bullet variant` | `2L/3L mix` | 3-line bullets allowed in CV for richer detail |
| `Skills config (resume)` | `4-3-2-2-2` | 13 lines across 5 skill groups |
| `Skills config (CV)` | `4-4-3-3-3` | 17 lines across 5 skill groups |
| `Immigration line` | `Yes` | Adds "Authorized to work in the United States" below skills |

### Provenance Flags

This is the anti-fabrication core of the kit. Every skill reads this table before generating any output. Add one row per paper or tool — the `Correct Framing` column is exactly what skills will use when referencing that item.

| Column | Purpose |
|---|---|
| `Item` | Short name for the paper or tool (match how you refer to it in extractions) |
| `Status` | `published`, `under review at [Journal]`, `preprint`, `internal`, or `draft` |
| `Correct Framing` | The exact phrase to use — skills copy this wording, never improvise |

Skills enforce these rules strictly: a paper marked `under review` will never appear as "published", and an internal tool will never be described as peer-reviewed. See [Anti-fabrication Rules](/concepts/anti-fabrication) for the full enforcement logic.

### KB Corrections Log

A table of verified factual errors to never re-introduce. Add entries as you catch them during critique or review.

| Column | Purpose |
|---|---|
| `Correction` | Short description of what was wrong |
| `Details` | The correct value and context, specific enough that Claude can apply it unambiguously |

### Role Types

Define every audience you're applying to. Each role type gets its own bundle during `/setup-build-kb`, and `/make-resume` uses the JD keywords to select the right bundle automatically.

| Column | Purpose |
|---|---|
| `Role Name` | Short label (e.g., `Academic`, `Industry R&D`, `National Lab`) |
| `Target Employers` | Who you're targeting with this role type |
| `Tier` | 1, 2, or 3 — see tier guide below |
| `Bundle File` | The bundle filename `/setup-build-kb` will create (e.g., `bundle_academic.md`) |

**Tier guide:**
- **Tier 1** — Strongest evidence, full portfolio. Your primary target audience. Lead with your highest-impact work.
- **Tier 2** — Strong fit with targeted emphasis. Some achievements need reframing to match this audience's priorities.
- **Tier 3** — Viable with careful framing. These roles are a stretch; the bundle will include explicit framing guidance to bridge the gap.

### Role-Type Decision Tree

A keyword mapping table that tells `/make-resume` which bundle to load for a given JD. Customize the `If JD mentions...` column to match your domain vocabulary.

| Column | Purpose |
|---|---|
| `If JD mentions...` | Keywords or phrases to scan for in the JD text |
| `Primary profile` | The Role Name to use as primary bundle |
| `Secondary (hybrid)` | Optional secondary bundle when roles overlap; use `--` if not applicable |

### FIXED Sections

A list of template sections that skills must never modify during generation. These are copied verbatim from your LaTeX template every time — no JD-specific changes, no bullet swaps. Typically: Education, Publications (CV), Honors & Awards, and the header block.

### Output Rules

Specifies package format and compilation expectations.

| Field | Notes |
|---|---|
| `Email in all outputs` | Must match Personal Info email — used as a cross-check |
| `Resume package` | Page count + cover letter format (e.g., `2 pages + 1-page cover letter`) |
| `CV package` | Page count + cover letter format |
| Output format | Always `.tex` only — you compile locally with your LaTeX distribution |

## Complete filled-in example

The following is Dr. Jordan Chen's `config.md` — the fictional computational biologist whose work is used throughout the example files in `resume_builder/examples/`.

```markdown
# Configuration

> Edit this file with your personal details. Every skill reads this file.

---

## Personal Info

- **Name:** Jordan Chen
- **Degree suffix:** Ph.D.
- **Email:** jordan.chen@email.com
- **Phone:** +1 5551234567
- **Location:** Richland, WA 99354
- **LinkedIn:** linkedin.com/in/jordanchen
- **Google Scholar:** scholar.google.com/citations?user=XXXXXXXXX
- **ORCID:** orcid.org/0000-0002-XXXX-XXXX
- **Website:**

---

## Document Preferences

- **Resume pages:** 2
- **CV pages:** 5
- **Resume bullet variant:** 2L (all variable bullets are 2-line)
- **CV bullet variant:** 2L/3L mix
- **Skills config (resume):** 4-3-2-2-2 (13 lines, 5 groups)
- **Skills config (CV):** 4-4-3-3-3 (17 lines, 5 groups)
- **Immigration line:** Yes | "Authorized to work in the United States"

---

## Provenance Flags

| Item | Status | Correct Framing |
|------|--------|----------------|
| Enzyme solvent tolerance paper (Chen, Yamamoto, Holmberg) | under review at Proteins | "under review" -- never say "published" |
| Screening pipeline tool | unpublished internal tool | "computational infrastructure I developed" -- never imply peer-reviewed |
| Stability database preprint | preprint on bioRxiv, not yet submitted | "preprint" -- do not say "published" or "under review" |

---

## KB Corrections Log

| Correction | Details |
|-----------|---------| 
| Transfer learning framework credit | Co-developed with M. Rivera. Always use "Co-developed", never "Developed" alone. |
| ESM-2 stability prediction accuracy | 0.82 Spearman (not 0.85). Confirmed in published Table 2. |

---

## Role Types

| Role Name | Target Employers | Tier | Bundle File |
|-----------|-----------------|------|-------------|
| Academic | R1 research universities, teaching-focused colleges | 1 | bundle_academic.md |
| Industry R&D | Biotech/pharma companies | 2 | bundle_industry_rd.md |

**Tier guide:** 1 = strongest evidence, full portfolio | 2 = strong with targeted emphasis | 3 = viable with careful framing

---

## Role-Type Decision Tree

| If JD mentions... | Primary profile | Secondary (hybrid) |
|-------------------|----------------|-------------------|
| tenure-track, faculty, assistant professor, teaching | Academic | -- |
| university, department, graduate students, NSF, NIH | Academic | Industry R&D |
| ML, machine learning, data science, R&D | Industry R&D | Academic |
| protein engineering, drug discovery, biologics | Academic | Industry R&D |
| pharma, biotech, clinical pipeline, GMP | Industry R&D | -- |

---

## FIXED Sections

- Education
- Publications (CV)
- Honors & Awards
- Header block (name, contact, links)
- Undergraduate Research Experience (2 bullets, never changes)

---

## Output Rules

- **Email in all outputs:** jordan.chen@email.com
- **Resume package:** 2 pages + 1-page cover letter
- **CV package:** 5 pages + 1-2 page cover letter
- **Output .tex files ONLY** -- user compiles locally
```

## After configuring

<Note>
Once your `config.md` is complete, open the LaTeX templates in `resume_builder/templates/` and fill in your FIXED sections — the `[CONFIG: ...]` placeholders mark everything that needs your content: education, publications, awards, and the header block. These sections are set once and never touched by generation skills.
</Note>

With `config.md` filled in and your FIXED sections populated in the templates, you're ready to extract your papers. See [Extract Papers](/setup/extract-papers) for the next step.
